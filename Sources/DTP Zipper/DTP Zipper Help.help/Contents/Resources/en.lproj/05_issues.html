Problems and Solutions

These messages appear in the Problem column of the Name Check window. They are grouped here by cause.

A message marked Stop must be fixed before you can compress. With a message marked Warning, you can review it and click Continue to compress.

Characters That May Be Garbled

These appear only when the encoding is Shift_JIS. The characters may be garbled on either Windows or Mac. Fix the name in the Finder, or change the encoding to UTF-8.

Platform-dependent character or similarStop
① ㈱ 髙 﨑 Ⅸ № ～ － ∥ ― ｩ
Character incompatible between Windows and MacStop
〜 − — ‖ ¢ £ ¬ ‾
The wave dash 〜 and the minus sign − are especially common when typing on a Mac.
Character not in Shift_JISStop
𠮷, é, emoji, and others
User-defined characterStop
Characters that a user registered independently (private-use characters, or gaiji). They don't display unless the recipient has the same characters registered, so none of them can be used.

When a name has characters of more than one kind, each kind is listed on its own row.

Note The Shift_JIS conversion table maps the ASCII tilde ~ to a different character, but you can use it in DTP Zipper. It's extracted as ~ from the ZIP file.

Names That Depend on the Extracting Software

Depending on the software used to extract the ZIP file, these names may not be restored correctly. Both are warnings, so you can review them and compress.

May not extract correctly. Putting it in a folder avoids thisWarning
Appears only when the encoding is Shift_JIS, when you directly drop a file whose name contains a character such as 表, ソ, or 能. Some software treats these characters as a folder separator, which breaks the name. To avoid this, put the file in a folder and drop the folder. Files inside folders and folder names aren't affected.
Compatibility ideograph (may change to a unified ideograph)Warning
Appears only when the encoding is UTF-8. Depending on how the extracting software processes names, a compatibility ideograph may change to a similar-looking unified ideograph. You can compress anyway, but for documents that find links by name, check the names after extracting.

Names That Can't Be Used on Windows

These appear regardless of the encoding. Windows can't use these names or can't handle them correctly. Fix the name in the Finder.

Character not allowed on WindowsStop
/ \ ¥ < > ? " | : * can't be used in Windows file names. Replace the character.
Reserved name on WindowsStop
CON, PRN, AUX, NUL, COM1–COM9, and LPT1–LPT9 are used by Windows. This applies regardless of case, and even with an extension, as in con.txt. Choose another name.
Ends with a space or periodStop
Windows can't handle a space or period at the end of a name correctly, so it may not extract properly. This applies to both file and folder names. Remove the trailing space or period.
Same name except for case at the same levelStop
The same level has items whose names differ only in case, such as A.txt and a.txt. When extracted on Windows, one overwrites the other. Rename one of them.
Control characterStop
The name contains a character you can't see, such as a line break or a zero-width space. Retype the name.
Path too longWarning
The path inside the ZIP file is 200 characters or longer. The Windows path length limit also counts the path of the folder being extracted to, so extraction may fail. Use fewer folder levels or shorter names.

Items Not Included in the ZIP File

This appears regardless of the encoding.

Aliases and symbolic links aren't included in the ZIP fileWarning
Aliases and symbolic links don't go into the ZIP file, and neither do the original items they point to. If you need the originals, put them in the folder. Special items that are neither regular files nor folders are treated the same way.

Fonts That Break When Compressed

These appear regardless of the encoding. Older font formats, such as Mac font suitcases and Type 1 fonts, keep their data in a resource fork. Resource forks can't be stored in a ZIP file for Windows, so compressing would lose the data and leave an empty file. DTP Zipper tells you instead of compressing.

Font whose data would be lostStop
The file is a font.
File whose data would be lostStop
The file isn't recognized as a font, but likewise has data only in its resource fork. A font that has lost its file type information also shows this message.

If your items include these files, don't use DTP Zipper. Compress them with the Compress command in the Finder. Fixing the name won't solve the problem.

Important Fonts don't break in a ZIP file made with the Compress command in the Finder. However, extracting it on Windows loses the resource fork and leaves an empty file.
Note Fonts that keep their data in the data fork, such as OpenType (.otf) and TrueType (.ttf), can be compressed without any problem.
