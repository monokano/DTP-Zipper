Encoding

In DTP Zipper, you can choose the encoding (character code) of the names stored in the ZIP file: UTF-8 or Shift_JIS.

Which to Choose

UTF-8 (default, recommended)
An encoding whose names don't become garbled when extracted on either Windows or Mac. Windows 8 and later and macOS support it as standard. Names don't become garbled even when the system language isn't Japanese. There are almost no restrictions on characters, so you can use ①, 髙, emoji, and more. Unless you have a particular reason, choose UTF-8.
Shift_JIS
Use this only when the recipient extracts files with an older app that doesn't support UTF-8 ZIP files, such as Lhaplus. DTP Zipper compresses only when every name won't become garbled on either Japanese Windows or Mac. As a result, the available characters are limited.
Important Even on Windows, Shift_JIS ZIP files become garbled in these environments:
  • The system language isn't Japanese (the ANSI code page isn't CP932).
  • The system language is Japanese, but "Beta: Use Unicode UTF-8 for worldwide language support" is turned on.

Characters That May Be Garbled on Windows or Mac

DTP Zipper creates ZIP files whose names don't become garbled on either Windows or Mac. So when the encoding is Shift_JIS, it doesn't compress names containing characters such as ①, 髙, the wave dash 〜, emoji, or user-defined characters. Fix the name in the Finder, or choose UTF-8.

For the list of these characters, see Characters That May Be Garbled.

Composing Dakuten and Handakuten Marks

On a Mac, a Japanese character such as が in a file name can automatically be split into two parts: か and a voicing mark (a combining character sequence). DTP Zipper composes combining character sequences into single characters in the ZIP file, with UTF-8 as well as Shift_JIS. This doesn't break links in Adobe DTP apps.

Compatibility ideographs, which normal composing would change into unified ideographs, are stored as they are without composing.
